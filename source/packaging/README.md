## Start

1. Start Infinite Warfare from the normal Steam library entry
2. Host a custom Zombies match and spawn
3. Run the **IW Zombies — Injected Menu** shortcut
4. Return to the game, hold aim, and press melee once
5. Select **Connect after spawning** with the use key

Saved keyboard bindings are read without changing the game's configuration.
With the current bindings:

- Open: hold right mouse and press **V** or the bound side mouse button
- Move up/down: aim/fire, or the bound up/down arrow actions
- Select: **F**
- Back / close: **V** or the bound side mouse button; Quick Exit behavior is described below
- Preview a preference choice: saved action slots 3 / 4, currently **3 / 4**
- Apply the previewed preference choice: **F**

Hold aim/fire for scrolling at the reference default interval. Release melee and
use between presses. Opening briefly shows paused help while the HUD appears;
normal controls resume 550 ms after its redraw. Row fades can continue after that
wait. Inputs pressed during opening are discarded, so release and press again
when the normal saved-key hints return. The instructions show the saved keys. Input also reaches the game; the menu does not
block movement, firing, or melee. There is no external menu or console window.

## Features

- **Basic Scripts** contains personal Godmode
- **Players Menu** lists detected players and provides guarded teammate Godmode
- **All Players Menu** contains Infinite Ammo, which affects the entire lobby
- **Menu Customization → Menu Credits** shows the original BO3 reference credits
  with scrolling text and fades; fresh melee returns early
- **Menu Customization → Width Editor** resizes the local panel within 200..500,
  with a live increment within 1..10
- **Menu Customization → Reposition Menu** moves the local panel with saved action
  slots 1–4; saved frag/tactical keys change the movement increment within 1..10
- **Menu Customization → Menu Instructions** controls visibility, alternate style,
  background, adaptive positioning, Reposition and Reset Position
- **Menu Customization → Main Design Color** offers the exact 36 reference colours
  with the active choice checked, plus Smooth Rainbow
- **Menu Customization → Menu Preferences** follows all twelve reference rows:
  Design, Bool Display, Bool Box Location, Scroll Animation Time, Quick Exit,
  Disable Quick Menu, Spotlight Cursor, Colored Cursor, Large Cursor,
  Option Counter, Stealth UI, and No Target While In Menu

No Target While In Menu remains unavailable. Disable Quick Menu changes the
local Quick policy; actual Quick opening is still unavailable pending player-state
and menu-permission validation. Menu Instructions
has its own submenu. Stealth UI limits the menu to five visible rows, changes Boxes
to Text, and clears the counter. Disabling it leaves those cleared settings unchanged.
Boxes and Option Counter cannot be enabled while Stealth UI is on.

Smooth Rainbow starts the source color cycle. Selecting it again keeps it running; choosing a fixed color stops it. The native cycle uses an independent uptime phase and lasts about ten seconds.

Menu Credits finishes automatically after its nominal 40-second sequence and
returns to the same customization row through the brief rebuild/pause. It uses
only the saved melee key; ordinary menu navigation and Quick Exit are inactive
during the presentation. Releasing melee allows a fresh retry if an exit was
rejected during a focus change. Closing or stopping the menu cancels the sequence.
The credits identify the BO3 reference separately from the IW backend and bundled
dependencies. [Credits evidence](../docs/menu-credits-reference-audit.md) records
the source timing, attribution wording and rendering differences.

Design offers Apparition, Classic, Native, AIO and Basic. The choice keys preview
a candidate; Use applies it. Changing designs briefly rebuilds the panel and
pauses menu input until the nominal 250 ms boundary. Applying the same design
also consumes that short input pause. Classic and Native disable Colored Cursor;
AIO and Basic disable Option Counter. Returning to Apparition makes compatible
controls available without restoring flags cleared by another design. Settings
last for the controller lifetime. [Design evidence](../docs/menu-design-reference-audit.md)
records source geometry and the opening-fade, color-history and brief footer
placement limits of that preceding checkpoint. A changed design now fades its
rows in over visible-ordinal durations while the independent input pause ends.
Scrolling continues from each row's displayed opacity. Normal opening and
reopening now retain the selected page and cursor, rebuild after 50 ms and wait
another 550 ms from the actual redraw before controls resume. Late redraws keep
that complete remaining wait. Other source callers remain separate work.
[Opening evidence](../docs/menu-opening-reference-audit.md) records the tested
state, rendering and remaining timing differences.
[Normal opening evidence](../docs/menu-initial-open-reference-audit.md) records
fresh-row binding, input consumption and adaptive help while the HUD is absent.

Quick Exit and the three cursor toggles briefly pause menu controls. Their
checkbox/style redraw follows after 180 ms; normal menu input resumes from the
nominal 430 ms boundary. The panel stays visible and the footer explains the
pause. [Refresh evidence](../docs/preference-refresh-reference-audit.md) records
which preferences use this timing.

Stealth without a counter uses the same 180/430 ms refresh. Changing Option Counter,
or enabling Stealth while a counter is present, briefly rebuilds the panel and
pauses input for the chosen native 250 ms interval. This layout feature does not
exclude the menu from recordings or streams. [Stealth evidence](../docs/stealth-ui-reference-audit.md)
records the reference rules and timing limits.

Display and box-location choices show a candidate and an applied value. The
choice keys change the candidate; Use applies it. Both saved action-slot bindings
are required. Missing bindings leave those choices unavailable with help.

Scroll Animation Time uses the same draft and Use controls. It shows actual
milliseconds: 120 ms by default, 100..250 ms in 10 ms steps, wrapping at the bounds.
The applied duration controls cursor movement, row transitions, selection fades
and font growth. Normal held scrolling waits that duration plus 75 ms. A change
applies to the next transition; movement already in progress keeps its duration.
Page/layout changes and observed focus gaps reset motion. These are source and
isolated-fixture results; live-game acceptance remains pending. The
[scroll audit](../docs/scroll-animation-reference-audit.md) records the source's
misleading displayed units and remaining timing differences.

Reposition uses the exact saved action slots 1–4 for Up/Down/Left/Right in eight-unit steps; melee returns to Menu Instructions. Instructions must be visible, and all four saved slot groups must exist. Aim/fire remain ordinary scrolling controls. Reset Position restores the current style's default anchor. Positions may be offscreen; Reset remains available when instructions are hidden. Entry and exit pause controls briefly. These settings last for the controller lifetime.

Reposition Menu is a separate editor. It opens immediately, keeps the customization
title, and replaces options with seven control hints. Movement applies live using
the current increment, which starts at 1 on each visit. Frag increases it and
tactical decreases it; melee returns to the same customization row through the
existing brief rebuild/pause. Position survives closing/reopening for the
controller lifetime. The ordinary instruction footer retains its own position;
Adaptive Position follows the moved menu. Saved positions are unclamped and may
be offscreen; editor status shows X/Y and increment. All seven exact action groups
are required. Missing bindings leave this editor unavailable with help. The
[reposition audit](../docs/menu-reposition-reference-audit.md) records source
geometry, inferred text spacing, input timing and proof limits.

Quick Exit defaults **OFF**. With it off, fresh melee returns one parent or closes
the root immediately. With it on, a child-page tap returns its parent on release;
a held melee gesture closes the local menu after the nominal 90 ms threshold.
The root closes immediately in either mode. The 20 ms input poll, acknowledgements
and scheduling can delay visible response. Closing the menu preserves controller-local
page/cursor and does not stop the controller, restore/disable game features or exit
the game; the **Exit** row remains the separate cleanup action.

The dedicated Width Editor uses exact saved Attack to widen, ADS to narrow,
action-slot 3/4 to decrease/increase the increment, and fresh melee to finish.
All four saved capabilities are required; unavailable bindings show help rather
than guessed controls. Changes apply live and remain when leaving; no Use commit
or rollback is involved. Fire takes priority over aim, then slot 3, slot 4 and
melee. Nominal held repeats are 75 ms for width and 125 ms for increment, subject
to 20 ms polling and acknowledgement delay. Inputs still reach ordinary gameplay.
The editor suppresses normal title/options/counter, shows five actual saved
control hints and replaces inactive footer Scroll/Select help with contextual
editor/Exit help. Normal footer instructions resume unchanged on return.

The integrated timing wave adds 50 ms linear presentation interpolation for width
changes. Committed width remains immediate; exact BO3 engine easing is unproved.
Finishing starts a local return sequence: panel hidden for elapsed 0..49 ms,
parent panel visible with controls paused at 50..149 ms, controls unlocked from
150 ms. The independent footer and IW status remain visible according to their
own visibility rules. All ordinary menu commands, including Toggle and Close,
are blocked during the return; owner shutdown remains separate.

The controller checks transitions every 25 ms, publishes changed display state
separately from its monotonic 100 ms heartbeat, and the native worker polls every 20 ms.
IPC acknowledgement and scheduling add quantization, so these clock thresholds
are not promises of exact rendered-frame timing. Held keys are consumed/reseeded
instead of replayed after return. Width persists only for controller lifetime
and changes no game configuration, map behavior or teammate HUD.

The integrated main timing wave has 441 confirmed distinct checks, a successful

## Stop and diagnostics

Choose **Exit** to stop the controller and restore its owned feature changes.
The inactive DLL stays loaded until the game exits. Do not attempt to unload it
or run another RTM/overlay controller in the same game session. A new attempt
after failed initialization requires restarting the game.

Session logs are private files under `$XDG_CACHE_HOME/iw-apparition-injected`
(normally `$HOME/.cache/iw-apparition-injected`). `current-session.json` identifies
the latest initialized session. `runtime-ready.json` means initialization finished;
`renderer-status.json` with a positive `drawnFrames` proves an actual successful
presentation. `bootstrap-error.json`, `runtime-error.json`, and `status.json`
provide failure details. Input-worker failure, graphics faults, or a stopped
controller heartbeat request graceful feature cleanup through the launcher.

The graphics guard currently supports Direct3D feature level 11.0. Unsupported
devices skip drawing and report a fault. The launcher supports alternate Steam or
game locations through `--steam-directory` and `--game-directory`.
