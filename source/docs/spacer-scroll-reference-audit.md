# Spacer scroll presentation

This wave implements the source paths around typed blank rows after an accepted
ordinary menu command. The reviewed source and isolated evidence are retained in the spacer-scroll
checkpoint. Installed files remain unchanged. The preceding opening-controls
checkpoint remains preserved as the baseline.

## Source and branch boundaries

The fresh official Apparition base matches commit
`307e94c1b1d6537ba7a2a71b32a22d563d3ea25c`. Its window-shift branch runs before
blank validation. A stable blank window waits half the scroll duration per blank,
then starts the final row, style and scroller transition. The visual option counter
changes at that boundary while action selection already names the confirmed row.

Current Open Controls has one blank at index 2. Capacities 8–14 retain window zero
for 1→2→3 and the reverse. Stealth capacity 5 has two different paths. Down holds,
then shifts the window and styles. Up shifts toward the blank window immediately,
then recreates the retained rows and scroller after the half-duration wait. Only
its detached outgoing row continues the original fade. Stealth disables the counter.

The planner also covers nonwrapped multiple blanks when every invalid-step window
stays unchanged, and a single shifted blank followed by a valid row. The latter
may have three distinct source, blank and final windows. Ambiguous shifted multiple
blanks, long wraps and unproved short-wrap variable semantics retain static fallback.
Those exclusions prevent a distance-only animation from claiming source behavior.

## Dispatch, state and drawing

A successful private command write and pending-command admission capture a bounded
plan. The parser promotes it only for the exact raw ACK, expected target, navigation
revision plus one, and unchanged menu, focus, policy, appearance and row identities.
JSON cannot supply this receipt. No new public command, raw key, feature writer,
engine offset or graphics lifecycle behavior is added.

Dispatch, completed-read observation and rendering use the existing GetTickCount64
clock. Input admission keeps its existing steady clock. Changed contexts, dropped
or jumped ACKs, stale state, clock rollback and expired history cancel the plan.
Late frames advance from dispatch time instead of restarting on each heartbeat.

The renderer requires a previously observed source frame and never invents one
on startup or reset. The confirmed selected row remains final throughout drawing.
A separately validated counter paint index retains the old number during the hold.
Window movement, row weights and the single bounded detached row follow the
classified path. The borrowed receipt pointer is cleared from retained requests.

## Fidelity and acceptance limits

Font metrics and engine easing remain unproved. Native interpolation retains the
existing linear mapping. An interrupted opening retains the bounded sampled alpha
history during the hold; its independent BO3 tween is not extrapolated through the
hold. File polling, publication and frame scheduling still quantize observation.

Isolated regression evidence is separate from retail frame/input acceptance and
from the unresolved saved match-exit fatal. This wave does not establish a crash
fix, gameplay feature success, Quick Menu, persistence, engine gates, other menu
families or IW map, quest and super-EE behavior. Full parity remains active work.

## Test-driven findings

Behavioral failures preceded each major correction. The producer case rejected
the old 180-profile inventory. The planner omitted valid ordinary/Stealth branches.
The parser initially failed to stamp the trusted receipt before publication.
Presentation failures covered late unchanged source reports, future/regressing
report clocks, the intermediate blank window, and direct-helper clock rollback.
Final tests cover those failures alongside invalid context and bounded fallback.
Build setup and test-oracle mistakes are separately recorded and do not count as
behavioral RED evidence.

Independent root checks pass the full native cross-build, strict .NET8 Windows
publication, Windows runtime 164, Windows scroll 34 and retained opening 9/12.
Portable CTest passes 12/12; CPU CTest passes 3/3. All four preview-order cases
pass across forward, reverse and relocated exports, with exact 252-image hashes.
The 210 preceding PNGs remain pixel-identical. Owned D3D11 modes report 42 normal,
60 closed, 47 opened and 69 active-transition assertions. Those assertion counts
are separate from the 1,256-case logical inventory and from retail acceptance.
