# Retained personal capture serialization

Explicit personal refresh previously completed a strict local capture before waiting for shared registry admission. A deterministic regression holds a real registry OFF action, starts refresh, then makes the strict reader unavailable before releasing the action. The old implementation returns success and leaves `CanToggle=true` from the earlier proof. A separate cancellation regression shows a queued refresh already consumed a strict read before cancellation.

A retained full binding, including one captured before an adapter was constructed, now submits its existing identity to the prepared capture path and waits for registry admission before strict local capture. The same implementation supports background recovery with a nonwaiting admission attempt. The existing local session still checks its complete latched account/actor binding, command clock and owned flags. No target is guessed or replaced and no game write path changes. Initial discovery remains local-first because no known identity exists yet; that path releases its local gate before entering the registry.

Both existing-adapter and latched-but-unbound cases are covered. The healthy post-admission case succeeds with OFF and `CanToggle=true`. Unavailable fresh proof returns false with UNKNOWN and `CanToggle=false`, without replacing the binding or writing flags, health or ammo. A cancelled queued refresh reads no source, preserves the original owner, releases admission and permits a later clean capture. Existing background contention, retry, cancellation and shared OFF regressions remain in the session gate.

This uses the existing registry-to-local lock order used by shared actions and cleanup. Explicit refresh may make other registry actions wait for its source read; it does not use a second semaphore, stored proof or duplicate capture core. Frame projection continues using the existing operation marker after admission; a queued refresh does not claim a new marker before its turn.

Tests use real connection, registry and local session code with owned fixture storage. They establish the offline ordering fix, not the cause of the earlier retail UNKNOWN/OFF report. Normal Steam gameplay, co-op toggles, damage coverage, all maps and full Apparition parity still require later acceptance. Installed products and saved playable backups remain unchanged.
