## Source view and capability boundary

authority. Dead players have Respawn and, with authority, two server commands.
The declaration catalog remains unchanged.

selected-local identity and the expected process. Shape, identity equality,
matching life, menu permission and enabled controls must all agree before the
positive life branch is displayed. Unknown or mismatched facts produce only
unavailable Respawn. These checks cannot authenticate a provider, establish
freshness or prove the personal writer targets that identity.

For a fully supplied living view, God Mode retains the existing personal
capability/value/action guards. The other declarations remain disabled,
UNAVAILABLE and without action intent. Private Unlimited Ammo cannot borrow
the lobby-wide patch. The unresolved grenade token is represented by the
binding-neutral product caption Bind Noclip To Lethal Action.

and an unavailable binding. It cannot expose God Mode by copying connection,
slot, health or teammate capabilities. The real controller now renders this
owned Quick page instead of throwing for its page enum. Root metadata follows
the active family, so Back closes the Quick root locally. Existing Toggle still
opens Main, including after an owned Quick view closes. No public page link,
backend admission command or native route enables Quick opening.

An owned offline controller export, `quick-root-unbound.json`, joins that actual
page to the unchanged native parser and CPU renderer. PREVIEW and the unavailable
opening notice distinguish its current support. Direct fixture navigation does
not establish the source immediate-draw/550 ms runtime opening contract.

## Concrete remaining runtime proof

Static inspection of the installed Steam DLL establishes that the named
SteamUser export returns its cached SteamUser016 pointer. Normal initialization
fills that cache and Shutdown clears it. This is a concrete route to investigate
without owning initialization, shutdown or callbacks. It does not prove safe
borrowed-object lifetime during shutdown, and an external backend cannot call
an interface pointer in the game. The existing Microsoft ABI fixture establishes
return storage only; no real Steam interface call was made.

Aurora's surrogate identity cannot establish the normal retail SteamID-to-player
GUID mapping. Neither slot zero, a name nor the old personal health scalar proves
the local account. Life also remains separate: IW scripts distinguish engine
IsAlive, last stand, faux death and session state. The current teammate reader's
health/normal-movement restrictions cannot convert a rejected read into Dead.

A primary builtin table identifies an IsAlive candidate and the installed PE
corroborates its function boundary. The on-disk instruction body does not prove
its predicate or callable ABI. It remains a research lead, not a production
function address. Account mapping, exact life/session predicates, IW permission,
consumer generation/freshness and personal target binding still need proof.

The user is ready to test independently. This saved candidate is not ready for
an in-game feature test and remains disabled. The earlier successful match-exit
report used an unidentified build; its cause and this candidate's live acceptance
remain unestablished. Installed files are preserved. No game launch, injection,
live memory write or real Steam API call was used for this update.
