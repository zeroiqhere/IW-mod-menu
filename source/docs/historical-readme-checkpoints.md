Components are organized by responsibility:

- `native/loader`: bounded PE inspection, checked system loader resolution, bootstrap
- `native/render`: D3D11 hooks, graphics state restoration, menu drawing
- `native/runtime`: saved controls, bounded IPC, heartbeat and immutable snapshots
- `native/shared`: bootstrap and render snapshot types
- `backend`: serialized menu actions and existing retail feature coordinators
- `packaging`: private-session launcher, saved binding reader, desktop entry
- `tests`: isolated regression fixtures matching each component

No guessed engine input or drawing offsets are used. Only the existing feature
backend accesses game feature state after explicit Connect and feature actions.
Loader timeouts retain potentially live buffers; installed hook trampolines stay
resident until process exit. `StopOverlay` stops drawing without unloading the DLL.

## Build

```sh
cmake -S . -B build -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
dotnet publish backend/IW.Apparition.Backend.csproj -c Release -o backend/publish
```

MinGW, CMake, Ninja, and .NET SDK are required. Compiler runtimes are statically
linked into the native artifacts. The controller uses the existing .NET 8 Windows
Desktop runtime installed in Steam app 292730's Proton prefix.
