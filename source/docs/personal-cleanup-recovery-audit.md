# Personal Godmode cleanup and menu recovery

This checkpoint adds regression evidence for existing behavior; it changes no
production code or gameplay writer. The previous separate diagnostic package
remains the runtime build for later testing.

A successful explicit restoration publishes OFF with new toggling disabled.
Restoration uses the retained original flag owner and does not require a new
living read. The production observer later admits a matching alive host receipt
through shared registry coordination. It captures read-only eligibility for
the original binding. Only a later explicit menu selection may enable again.
The regression covers an observed host fixture; non-host availability is not
established.

The new real-session regression follows the actual personal menu row through
ON, rejected OFF, UNKNOWN with a pure Restore action, successful cleanup, OFF
with no enable grant, owned-observation recovery, and deliberate ON. It checks
local slots 0, 2 and 3, identity retention, one writer, strict capture, no writes
during observation, and unchanged peers, health and ammo. Existing all-slot
checks cover ordinary toggles; no extra fixture or production API is added.

All 252 candidate session checks pass. Two isolated mutations demonstrate that
the new test rejects both premature enable permission after restoration and
missing OFF recovery. Independent final source checks are recorded with the
checkpoint evidence. This proves the portable session/menu behavior, not retail
damage coverage, the earlier UNKNOWN/OFF cause, co-op, all maps or Super EE.
