# Held mechanical source branches

The ordinary monitor now retains the successfully written choice or Back invocation through its own finite source wait. When that wait normally ends, the current key levels resume in source branch order. A nonslider attempt resumes after 50 ms, a slider attempt after 180 ms, and a final Back/Close/Jump result after 250 ms. The native input router never calculates those deadlines. This source candidate does not establish full Apparition parity or retail gameplay acceptance.

## Source and branch contract

The official Apparition source checked with curl remains commit `307e94c1b1d6537ba7a2a71b32a22d563d3ea25c`. The [ordinary monitor](https://github.com/CF4x99/Apparition/blob/307e94c1b1d6537ba7a2a71b32a22d563d3ea25c/Menu/base.gsc#L61-L169) checks scroll, Use, exclusive choice slots, then knife or dead Quick Jump. A declared slider adds an inner 130 ms to the outer 50 ms; a nonslider choice reaches only that outer wait. Final Back decisions add 200 ms to the same outer wait. Opposed choice slots fall through to the later branch.

Direct [newMenu](https://github.com/CF4x99/Apparition/blob/307e94c1b1d6537ba7a2a71b32a22d563d3ea25c/Menu/base.gsc#L927-L1016) rebuilds its actual parent and clamps its saved row cursor without an intervening monitor wait. No fixed navigation increment describes that result. [closeMenu and closeQuickMenu](https://github.com/CF4x99/Apparition/blob/307e94c1b1d6537ba7a2a71b32a22d563d3ea25c/Menu/base.gsc#L223-L299) destroy the body while retaining the current page family. A closed child is consequently legitimate; closed Back readiness never grants ordinary input or a new opening gesture.

Quick Exit retains its admitted knife loop. Releasing before its 90 ms boundary admits Back; continuing the hold admits Close. That decision precedes the independent final 250 ms pause. The loop stays exclusive while it is active.

## Captured command and publication

The new optional `menuMonitorContinuation` has exactly four fields: positive unsigned `revision`, `sequence`, `admissionRevision`, and `kind` (`choice`, `choiceNoop`, or `back`). Its sequence cannot exceed the packet acknowledgment. While waiting, its revision and kind must equal the actual `menuMonitorWait`. The producer retains it only after normal expiry, under the same private owner, admission, page topology and relevant target scope. Cancellation, lost focus or authority, independent navigation, competing callbacks/editors/rebuilds and shutdown withdraw it. A backend clock rollback restarts the finite wait; native time cannot end it.

Modern choice/Back/Close/Jump commands carry their original `navigationRevision`, `localAdmissionRevision`, and `menuRevision` as one complete scope. The controller rejects a stale or partial scope before draft, navigation or wait mutation. The private capture retains row action/declaration topology and relevant selected-player, all-player cohort and personal-action identity. No memory address or player capability is supplied by the receipt.

A Back result binds only its own actual rebuilt and clamped rows. The first successfully created state document commits that result. A failed publication retains an exact retry candidate without granting readiness or adopting an independent navigation change. The native router captures its command sequence only after the command file was written and the command gate marked it sent. It requires that exact acknowledgment and a fresh receipt revision before resuming current levels. Missing metadata and rejected dispatch capture consume inherited timers and holds.

## Compatibility and visible behavior

The new properties are appended and omitted when null. Older command envelopes and router calls that omit the mechanical contract retain the existing legacy behavior and byte-identical fixture packets. This is an API compatibility claim; a new injected worker uses the paired modern producer contract. Mixed installed backend/DLL combinations have not been accepted.

The modern source behavior no longer forces nonslider choice attempts to use the native 180 ms repeat timer. Direction reversal, release/repress, a newly held Use or a newly held knife are sampled when the original invocation normally retires. The published draft and applied preference stay separate. Declared but unavailable gameplay sliders remain visibly `UNAVAILABLE` and gain only the source attempt pause, not a gameplay callback.

## Evidence and limits

The organized focused native checks cover source durations, current branch priority, own parent/closed results, failed writes, malformed receipts before key reads, missing proof, foreign acknowledgments/revisions, independent scope and life changes, focus and clock loss, and legacy omission. A genuine invalid-capture regression left a held repeat armed; resetting the full router on rejection fixes it.

A separate actual-controller export contains 55 immutable packets across eight graphs. Literal expected epochs, source rows, admission, visibility, wait/receipt/callback identity and both independent readers are checked before the native router joins held direction reversal and subsequent Use, repeated nonslider attempts, parent/root Back chains, child knife tap/hold close, dead Quick Jump, focus/navigation withdrawal, independent clock rollback and unavailable Ammo attempts. Native clock samples remain independent of controller time, and packet bytes are never rewritten to manufacture readiness.

The complete goal remains open: generic threaded submenu Use scheduling and current-row BOOL reread, remaining physical monitor predicates, all source menu/gameplay callbacks, private weapon ammo transport, resident preferences and game lifetime, certified retail player/cohort authority, physical drawing and engine fade, GPU/injection lifetime, normal Steam co-op across every map, quests and super EE acceptance. Source tests and Windows compilation do not prove those runtime requirements. The playable saved backup and installed disabled products remain untouched.
