# Selected-player observation and publication

This checkpoint preserves the Apparition selected-player menu and the shared
personal, teammate and All Players Godmode owners. It changes where observation
runs; it does not add an alternate writer or adopt a player from a displayed name.

## Display contract

`TeammateGodmodeSession.ReadView` copies a publication and checks cached registry
metadata and the proof-retirement revision. It never invokes a native identity
reader, flag preflight or feature factory. The complete retained owner stamp
includes other participants, because another failed restoration can restrict
selection and new enables. Adapter metadata failures produce UNKNOWN and no
action capability. Copied records remain immutable.

A fresh worker sample establishes the selected value and identity. Native changes
that have not yet been observed remain the previous copied sample until refresh.
Every action still runs fresh original identity and desired-state admission, so a
copied receipt alone cannot authorize a write. Invalid slot/name payloads only
change the notice and do not start a native query or erase a valid selection.

| Situation | Display and action behavior |
| --- | --- |
| Stable validated OFF or owned ON | Copied value and appropriate original toggle |
| Shared registry operation, metadata change or retired proof | UNKNOWN, target and toggle unavailable until refresh |
| Held refresh | Cached peer view returns UNKNOWN and no toggle without waiting for the peer reader |
| Same-name replacement | Fresh action rejects; observed original proof stays retired |
| Life-only death | Restoring an owned ON remains possible; a new ON needs living eligibility |
| Failed metadata getter | UNKNOWN, conservative cleanup indication, no frame exception |
| Closing | No new capabilities or confirmed gameplay values |

## Worker and lifetime

The existing retained session observation task also refreshes the selected peer.
A session without a local observation provider can still refresh a selected peer;
no peer selection and no provider retains the previous inert polling behavior.
Group polling refreshes peer metadata after its registry capture even without a
selected peer. Group and personal actions refresh the peer publication after
shared ownership changes. Refresh does not manufacture adapters or use capture
as polling.

The action and refresh gate is always released after publication failure. Source
cancellation during shutdown revokes observations without faulting default
polling; explicit caller cancellation still cancels only that caller's wait.
Shutdown joins the retained observation before waiting for Godmode owner cleanup.
A timed-out read skips owner closing and retains the original transport for retry.
No replacement connection is opened while cleanup remains blocked.

## Evidence and limits

Regression cases use real flag features and bound adapters over owned recording
storage. They cover frame read counts, held reads, shared round trips, another
owner's stopped monitor, same-name replacement, property failure and cleanup,
source cancellation, actual menu/target publication and shutdown retry. Earlier
frame-triggered tests now hold a worker refresh at the actual native boundary.
That migration preserves their generation and target assertions without requiring
native peer proof reads from rendering.

The subsequent connection-liveness wave removes frame reads of
`RetailSteamTransport.Connected` and `ProcessId`. Frames now read a connection-owned
cache, and retained workers sample the original process before and after source
queries. A recording transport with one shared native access lock exercises a held
actor query and proves that cached menu, target, observation, and opening-admission
getters finish without acquiring that lock. This establishes the managed frame
contract; actual retail rendering and native graphics responsiveness still need
runtime evidence. See `connection-liveness-reference-audit.md` for retirement,
new-write admission, and restoration details.

The source candidate and tests are separate from the installed menu and playable
backup. No game, injection, Steam prefix or installed files change in this wave.
Full Apparition callback parity, retail vacant-slot proof, personal ammo weapon
transport, physical drawing/input, normal Steam co-op, every map and the super
Easter egg remain incomplete or unverified. Offline checks cannot prove them.
